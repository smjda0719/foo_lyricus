# 歌词运动设计：横滚、上滑、遮罩

> 用户 2026-09-25 提：「我看到你对过长文本的换行处理了。不过不太美观。
> 趁这个机会我们规划一下这个问题。我的想法是让长歌词滑动起来。
> 另外，还可以实现滑动切换歌词，不过可能需要实现遮罩来防止歌词与标题重叠。」

这篇是**动手前的方案**。四个取向已由用户拍板（见每节末尾的「取向」）。

---

## 0. 先否掉两件"看起来很自然"的事

规划之前先把地基量了一遍（`lyricus-debug.log` + 源码），有三个事实直接决定了方案形状：

### 0.1 整帧重绘 5~10 ms，30 fps 全帧重绘吃掉主线程两成

日志里 `RenderLayered（重绘 + 提交）` 超 5 ms 的记录有 348 条，实测样本：

```
[01:03:17.207] 慢: RenderLayered（重绘 + 提交） 用了 10.5 ms
[01:02:58.948] 慢: RenderLayered（重绘 + 提交） 用了  9.2 ms
```

里面是**两遍逐像素循环**（`control_window.cpp:973` 铺底写 BGRA、
`control_window.cpp:996` alpha 修正 + 预乘），920×300 = 27.6 万像素各扫一遍。

> **所以：动画绝不能"每帧重画整个面板"。**
> 主线程是 foobar2000 自己的 —— D-031 那一整套节流就是为这个存在的。

### 0.2 alpha 是二值的，柔和淡出不是加参数就有的

```cpp
// control_window.cpp:998
if (p[0] != bgB || p[1] != bgG || p[2] != bgR) p[3] = 255;
```

"凡不是底色的像素一律不透明"。一个**淡出到一半**的文字像素仍然"不是底色"，
照样被拉到 255 —— 想在现有管线里做真正的渐变 alpha，得先改这条判据。

### 0.3 只有遮罩是绕不过去的

`DrawTextW` 只能裁到**它拿到的那个矩形**。而横滚需要的是
「**文字位置在动、裁剪框不动**」—— 传进去的矩形一动，裁剪框跟着动，等于没裁。
只有 `IntersectClipRect` 给 DC 设一个独立的裁剪区才能做到。

**所以遮罩不是"顺带做的防重叠"，它是横滚的前置条件。**

## 1. 遮罩（第一步，独立可验证）

```cpp
// 曲名画完之后、歌词画之前
const int saved = SaveDC(dc);
IntersectClipRect(dc, rc.left, lyricsTop, rc.right, limit);   // lyricsTop = 曲名下方
... 画歌词 ...
RestoreDC(dc, saved);
```

- `lyricsTop` 就是现在算出的 `y`（`rc.top + S(14) + 曲名行高 + S(8)`），
  `limit` 就是 `clipBottom` 或 `rc.bottom`（D-043 已经拆开了）。
- **横滚**靠它裁左右（文字画在 `[left - scrollX, ...]`，裁剪区固定 `[left, left + maxW]`）。
- **上滑**靠它裁上下（滑动的中间帧内容会越过 `limit`，进入控制条那一段）。

取向：**先硬裁**。柔和淡出留到以后 —— 它要先把 0.2 那条二值 alpha 改掉，
属于另一件事，不该混在这一轮里。

## 2. 三种行的绘制方式（一句话概括）

| 行 | 放不下时 | 绘制标志 |
|---|---|---|
| **当前行** | **横滚**（滚一次到尾部就停） | `DT_SINGLELINE \| DT_NOPREFIX` + DC 裁剪区 |
| **上下文行**（上下的） | **省略号截断** | `DT_SINGLELINE \| DT_END_ELLIPSIS \| DT_NOPREFIX` |
| **参照行**（译文小字） | 同上下文行，省略号 | 同上 |

三点说明：

1. **当前行必须单行**，否则没有东西可滚 —— 这会**撤掉 4d1c2e8 的折行**。
   那次改动方向没错（`DT_SINGLELINE` 既不换行也不给省略号，字是**直接没了**），
   但补的是"省略号缺失"，用折行来补代价太大。现在有更好的答案。
2. **上下文行回到单行**是个白捡的好处：上下文的行高重新变得**一致**，
   `above` / `below` 的堆叠间距恢复可预测。折行的副作用是长行把上下文顶得参差不齐。
3. **参照行**（翻译）不滚。滚动的只有正文 —— 两行各自滚会因为宽度不同而漂移，
   视觉上很乱。而"哪个是正文"由 `tlPrimary` 决定，所以翻译为主模式下**翻译滚、原文截断**，
   规则不分叉。

> ⚠️ `DT_NOPREFIX` 不能丢（歌词里的 `&` 会被当成助记符吃掉）。

## 3. 横滚的时间线

取向：**只滚一次，滚到能看见尾巴就停住**，直到换行。

```
t=0                      t=lead                    t=lead+dur
│──── 静止（先读开头）────│────── 匀速左移 ──────│──── 停在尾部 ────► 直到换行
offset = 0               offset: 0 → overflow      offset = overflow
```

- `overflow = textW - maxW`；`overflow <= 0` 的行**完全不动**，不启动动画
  （绝大多数行属于这种 —— 这是整个方案便宜的根本原因）
- `lead`：**900 ms** 停顿，让人先读开头
- `dur = clamp(overflow * 1000 / 60, 1000, 5000)` ms
  （基准速度 60 逻辑像素/秒；超长行封顶 5 s，靠提速而不是拖时间）
- 重置条件是**行号变了**，不是时间回跳 —— 所以往回 seek 到同一句不会重滚

## 4. 上滑过渡

换行时整块歌词向上滑动 ~200 ms，而不是硬切。

**实现**：给渲染层加一个 `slideY`（**画面整体下移**的像素数，0 = 最终位置）。
过渡期间 `slideY: step → 0`，所有歌词行的 y 都加上它。

- `t=0` 时整块比最终位置**低一步**（新当前行正好落在旧当前行的位置上），
  然后升到最终位置 —— 这就是"往上滑"。
- ⚠️ **往下偏的中间帧不会撞到曲名**：整块只从"低一步"升到"最终位置"，
  而最终位置本来就保证在曲名下方。撞的是**下方**：`t=0` 时最低一行比最终位置低一步，
  会越过 `limit` 压到控制条上 —— 所以第 1 节的遮罩在这个方向是必需的。
- `step` 取"上一行作为上下文行时的步距" ≈ `bodyLineH + gapNormal`。
  上一行原本用**当前行字体**（更大更粗）、现在变成**上下文行字体**，
  所以这不是一个精确的位移量 —— 200 ms 的过渡里看不出来，不做精确求解。
- **只对"顺序推进"生效**：行号正好 +1 才滑。往后 seek（行号变小）不滑，
  跨行 seek（+2 以上）不滑，换曲不滑。**往前正好跳一句会误滑一次** —— 无害，不值当为它加状态。

## 5. 动画驱动：第二个定时器

三个宿主现在各**一个** 250 ms 定时器（`control_window.cpp:50` id=1，
`dui_element.cpp:24` / `cui_panel.cpp:58` id=2）。

**加第二个定时器**（33~50 ms），只在动画期间存在：

| 定时器 | 周期 | 干什么 |
|---|---|---|
| 逻辑拍（现有） | 250 ms | `RefreshPosition()`、轮询配置、心跳日志 |
| **动画拍（新）** | 40 ms（25 fps） | **只重绘**，什么都不查 |

⚠️ **逻辑拍一点都不能动。** 它每拍要查 3 次 `fb2k::configStore`（`GetLyricDisplayConfig`），
提到 25 fps 就是每秒 75 次查表 —— 那是纯粹的浪费。

动画结束时（滚到尾部 / 上滑结束）**立刻** `KillTimer`，退回只有逻辑拍的状态。
配合"只滚一次就停"的取向，长歌词才活几秒，不是常驻。

## 6. 模块划分

新增 `src/scroll_anim.h/.cpp` —— **纯逻辑，不碰窗口、不碰 DC**：

```cpp
namespace lyricus {

// 一帧的动画输出
struct LyricAnimFrame {
    int  scrollX = 0;    // 当前行横向偏移（>=0，向右滚出去多少像素）
    int  slideY  = 0;    // 整块歌词的下移量（0 = 最终位置）
    bool animating = false;   // true = 宿主该让动画定时器跑着
};

class LyricAnimator {
public:
    // 每次逻辑拍和每次动画拍都调一次。now 由宿主给（GetTickCount64），
    // **不在内部取时钟** —— 单测要把时间轴推着走。
    LyricAnimFrame Update(ULONGLONG nowMs, size_t lineIndex,
                          int textWidth, int maxWidth, int stepPx);

    void Reset();   // 换曲 / seek / 配置变更时清掉
};

} // namespace lyricus
```

**渲染层保持纯函数**（无状态），只多接一个 `const LyricAnimFrame&`：

```cpp
int DrawLyricsView(HDC dc, const RECT& rc, const LyricsViewTheme& theme,
                   const LyricsViewLayout& layout,
                   const LyricAnimFrame& anim = {});
```

**宿主怎么拿到"当前行文本宽度"**：`DrawLyricsView` 的返回值从 `int`
改成一个小结构 `{ int bottom; int currentTextW; int currentStepH; }`，
宿主存下来，下一拍喂给 `Update()`。差一拍无所谓 ——
`Update()` 的重置条件是行号变化，不是宽度变化。

理由：这样 `LyricAnimator` 可以在单测里**把时间轴推着走**，
`静止 → 左移 → 停在尾部` 整条时间线离线可验证，不需要开窗口。

## 7. 性能预算与退路

先按**整帧重绘**实现，用现成的 `ScopedTimer` + 心跳量出来，**再决定要不要优化**。
不预先优化（这个项目一直是这个路子）。

预估：25 fps × 7 ms ≈ 175 ms/s ≈ 主线程 17% —— 偏高，但只在长歌词的头几秒。
日志会直接告诉我们真实数字（`RenderLayered（重绘 + 提交）` 已经挂了 5 ms 阈值）。

**退路已经想好，需要时再上**：**带状重绘**。动画期间只有当前行那一条在变，
所以每帧只重铺 / 重画 / 重预乘那一条（920×约 50 = 4.6 万像素，比整帧少 6 倍）：

1. `IntersectClipRect` 到那一条
2. 把那一条写回底色（BGRA）—— **必须从底色重写**，
   因为预乘**不是幂等的**（底色 alpha=215，乘两次会变暗；文字 alpha=255 才幂等）
3. 画文字
4. 只预乘那一条
5. 提交（可以试 `UpdateLayeredWindowIndirect` + `prcDirty` 只提交脏区）

不需要第二张 DIB：那一条每帧都从底色重算，天然不会二次预乘。

**先测再决定**，因为 5~10 ms 里有多大比例是 `UpdateLayeredWindow` 本身（DWM 合成）
还不清楚 —— 如果它才是大头，带状重绘省下来的比想象的少。

## 8. 单测要钉住什么

沿用 `tests/harness` 那套「渲染到内存 DIB 再按像素分析」的办法（不开窗口）：

**`LyricAnimator` 的纯逻辑**（把 `nowMs` 推着走）：
- 放得下 -> 永远 `scrollX == 0`，`animating == false`
- 放不下 -> `0..lead` 期间 `scrollX == 0`（停顿真的存在）
- 过了 `lead` -> `scrollX` 单调递增
- 到 `dur` 之后 -> `scrollX == overflow` 且**不再变**（"滚到尾部就停"）
- 行号 +1 -> `slideY` 从 `step` 降到 0，且 `dur` 之后为 0
- 行号跳变（seek）-> 不滑
- 行号回退 -> 不滑

**渲染层**：
- 长上下文行 -> **单条横带**且不超出 `maxW`（省略号生效，不再是折行）
- 长当前行 -> 画出来的墨迹**被裁在 `[left, left+maxW]`** 内（遮罩生效）
- 给不同的 `scrollX` -> 墨迹左右边界跟着移动（滚动真的作用在绘制上）
- 给一个很大的 `slideY` -> **曲名那一行一个字都不受影响**（遮罩挡住了）
- 给一个很大的 `slideY` -> 内容不越过 `clipBottom`（控制条不被压）

**要重写的旧测试**：`TestVeryLongLine` 现在断言的是"折行"（横带变多）——
那个结论随本轮作废，改成上面这几条。

## 9. 落地顺序

| 步 | 做什么 | 完了能验证什么 |
|---|---|---|
| 1 | 遮罩（`IntersectClipRect`）+ 上下文行改省略号 | 单测：上下文单条带、不超宽。**先把折行撤掉，画面立刻回稳** |
| 2 | `LyricAnimator` + 单测 | 时间线离线可验证，一行渲染代码都还没改 |
| 3 | 渲染层接 `anim`，当前行横滚 | 三个宿主同时生效（共用渲染层） |
| 4 | 宿主加动画定时器 | 真机看到滚起来；日志给出真实耗时 |
| 5 | 上滑过渡 | 换行不再是硬切 |
| 6 | 量性能，必要时上带状重绘 | 主线程占用 |

第 1 步就能单独交付 —— 它自己就让画面比现在好看（长上下文行不再把版面顶乱）。
