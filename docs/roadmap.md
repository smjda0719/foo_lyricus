## 二、架构地图

分层的依据只有一条：**能不能进离线单测台**。

```
┌─ 纯逻辑层（不碰 SDK，全部可离线测）────────────────────┐
│  lyric.cpp           LRC 解析、显示序号                 │
│  lyric_search.cpp    文件名匹配、模糊评分               │
│  online_lyric*.cpp   在线源解析、JSON、候选闸门         │
│  source_order.cpp    源顺序                             │
│  lyrics_view.cpp     排版与绘制（HDC，但不是 SDK）      │
│  scroll_anim.cpp     横滚/上滑时间线                    │
│  control_bar_layout  控制条降级布局                     │
│  prefs_layout.cpp    首选项页布局与配色推导             │
│  color_wheel.cpp     HSV 换算、色环几何、命中           │
│  color_util.cpp      BlendColor / ColorLuminance        │
│  folder_hint_table   歌词线索表                         │
└────────────────────────────────────────────────────────┘
              ↑ 上面这些都不敢 include SDK 头
┌─ SDK 层 ───────────────────────────────────────────────┐
│  config / settings   配置读写（cfg_var / advconfig）    │
│  playback_state      play_callback + 状态缓存 + 线程编排│
│  debug_log           日志（**主线程专用、无锁**）       │
│  folder_hint         cfg_var 那层壳                     │
│  dpi_util / ui_draw  共用小工具（theme 要问宿主，故在此）│
└────────────────────────────────────────────────────────┘
              ↑
┌─ 宿主层（三个平行实现）────────────────────────────────┐
│  control_window.cpp  独立置顶分层窗口（UpdateLayeredWindow）│
│  dui_element.cpp     DUI 元素                           │
│  cui_panel.cpp       Columns UI 面板                    │
│      └─ 三者都调 lyrics_view.cpp 里的 DrawLyricsView    │
└────────────────────────────────────────────────────────┘
```

**三处硬约束**（违反了会静默失效，不报错）：

1. **`DebugLog` 只在主线程用，而且没有锁** —— 后台线程调它会出乱子。
2. **`Process.MainWindowHandle` 不可靠** —— 它会挑中浮动面板（独立置顶窗口）。
   枚举窗口要用 `capture-ui.ps1` 里那套（UIAutomation 顶层 + 递归子窗口）。
3. **面板的 `WM_CLOSE` 是隐藏不是退出** —— 要重启播放器得给**主窗口**发。

## 三、★ 症状 → 决策 速查表

**看到下面这些"异常"时，它们都是特意设计的，不要"修"。**

| 你看到什么 | 决策 | 为什么 |
|---|---|---|
| 歌词开头有一条 `———` | **D-038 / D-040** | **特意补的分隔线**。网易云歌词开头是制作人员名单（作词/作曲/编曲），剥掉后补一条线代替空行 —— 空行要改解析器，而那全工程共用 |
| 面板显示「（纯音乐，请欣赏）」 | **D-056** | 在线源**明确说**这是纯音乐（不是"找不到"）。比笼统的「（无歌词）」精确 |
| 首选项里改字体**立刻生效**、改颜色要**点应用** | **D-082** | 两种模式并存是**有意的**：`ChooseFontW` 是模态的，点确定就是明确意图 |
| 浮动面板的字号不跟宿主 | **D-081** | **刻意**不填宿主字体 —— 它有自己的字号设置，跟着跳会让用户调好的值莫名其妙地变 |
| 色环拖到环外、角度还在变 | **D-076** | `takeHue()` **刻意不判半径** —— 角度在任何距离上都有意义 |
| 数值标签只在拖拽时出现 | **D-065** | 常驻是**刻意不做**的 |
| 纵向和横向音量条是两份代码 | **D-063** | **刻意没合并** —— 合并的收益不抵改动风险 |
| 曲名画在歌词遮罩**外面** | **D-044** | 它是这一屏**唯一允许**出现在歌词区上方的文字 |
| 热安装备份的后缀不是 `.dll` | **D-026** | **故意**的 —— 免得被 foobar2000 当成组件加载 |
| `ResetToDefaults()` 用系统 DPI 而非窗口 DPI | [`plan.md`](plan.md) | **复核后确认不是 bug**：它同时把位置重置成 `-1,-1`，而初始位置也是按系统 DPI 居中到主屏 —— 两者口径必须一致 |
| 缓存里只有部分歌有 `.lrc` | **D-051** | 被取消的那一轮**绝不写未命中标记** —— 否则一次随手切歌换来 7 天查不到 |
| `BlendColor(a, b, -0.5)` 是负的 | **D-077** | **外推**，`t` 为负 = 朝反方向推。DUI 靠它让当前行比正文更亮 —— 按"t 应在 0..1"收紧会静默毁掉那个高亮 |
| 面板窄到一定程度进度条整个消失 | **D-061 / D-062** | **有意的降级顺序**（按钮 > 进度条 > 时间 > 音量条），不是布局算错 |
| 拖动时进度条/音量条的数字跟着变 | **D-065** | 显示的是"**将会设置成**"的值，不是播放器当前值 —— `set_volume` 只在松手时触发 |
| 两个窗口的同一份工具函数各写一遍 | **D-077** | 曾经是；**已合并**进 `color_util.h`。若再看到重复，那是新的债 |

## 六、怎么验证

| 要验什么 | 用什么 |
|---|---|
| **纯逻辑** | `cd tests\harness; .\run.ps1`（9 组 694 项）<br>`-Suite <组名>` 只跑一组；`bench` 是搜索成本基准 |
| **界面长什么样** | `.\tools\capture-ui.ps1 -Target all`<br>`-List` 列出所有界面窗口；`-Restart` 先重启 |
| **改完立刻生效** | 守候进程（`tools\watch-install.ps1`）**默认不打断播放**，等你下次关播放器才重启。<br>要立刻重启用 `-Relaunch` |
| **打包** | `.\tools\package.ps1`（包比源 DLL 新就跳过） |

**验证界面时的两个坑**（`capture-ui.ps1` 里已经处理，但手工做时会踩）：

- **别用 `CopyFromScreen`** —— 它抓"屏幕上此刻显示的东西"，窗口被遮挡就抓错。
- **必须声明 DPI 感知** —— 否则 `GetWindowRect` 返回 DWM 虚拟化过的坐标，
  200% 缩放下截图整体错位。

**日志在哪**：`%APPDATA%\foobar2000-v2\user-components-x64\foo_lyricus\lyricus-debug.log`
（2MB 轮转成 `.1`）。

**怎么从日志判断卡顿**：找 `RenderLayered 分解:` 那行，看 **`距上帧=`**：
- 间隔正常（40/250ms）而耗时长 → **我们慢**
- 间隔明显偏大而耗时正常 → **被抢了**（优化代码没用）
